作用域切面 · 两条防护边界在哪里分开

关键差异不在 Agent 名单，而在插件装在哪。 2026-09-11 起 ASC 也开始支持 Cursor、Claude Code、Trae 等「终端型」Agent 的运行时防护，与 SASE 的覆盖名单高度重合。 但 ASC 的防御插件装在服务端 Agent 进程里做 RASP，SASE 的能力装在员工电脑上做终端管控。 证据：ASC 防御范围升级公告 · SASE AI资产管理

选 SASE
风险发生在员工用 AI 的办公场景——影子 AI 失控、数据被 Agent 带出办公网。
选 ASC
风险发生在你交付给客户的 Agent 应用本身——供应链、运行时、出站外传、上线前红队。
组合打法
SASE 管办公侧入口与员工行为，ASC 管业务侧自建 Agent 的供应链与运行时；两者在「会话审计 + 提示词防护」上能力口径接近。
入口
控制台同域相邻：?p=csas（SASE）与 ?p=sas#/agentAsset（ASC），容易点错。
