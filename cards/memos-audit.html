MemOS 评测取证：
它自己的尺子，和别人的尺子

MemTensor 的 MemOS 是这两年声势最大的 Agent 记忆系统之一。这份记录不谈架构好不好看， 只做一件事：把它所有的分数按来源拆开，钉在同一把 0–100 的量程尺上， 看哪些是它自己量的，哪些是别人量过的，两者差多少。

对象　MemOS / MemOS Cloud / memos-local-plugin 方法　3 路并行调研 + 主代理直连核验 一手来源　GitHub API · AML 榜单 API · npm · alphaxiv

零先给结论

要一句话的话，是这句

架构叙事和工程投入是真的，"评测领先"不是。
在唯一一个把答案生成与打分都收归平台的第三方榜单上，MemOS 排第 2；
在唯一给出误差棒的第三方重跑里，它只有 72.99，低于自己论文的 75.80；
而 README 上写的 88.83，来自它自家的评测框架。

它的真实强项是检索速度和写入容量；真实短板是记忆治理、冲突消解、规则与流程执行—— 最后一项恰好是它对外宣传的头号卖点"自进化 / 技能复用"，在受控榜单上只拿到 9.82。

一动手前先分开两个 "Memos"

这是这类调研里最容易出错的地方，先排除掉

名字是什么注意
usememos/memos 自托管轻量笔记应用（Go），与 AI 无关 网上搜 "Memos CVE" 命中的 CVE-2025-50738（CVSS 9.8）属于它 子代理核查
MemTensor/MemOS 本记录对象：LLM / AI Agent 的记忆操作系统 我方直连核验：未找到针对它的任何 CVE。已公开的安全问题都以 GitHub issue 形式存在 我已核验

把两者的 star 数、CVE、用户评价混在一起，结论就全错了。第三方站点 RightAIChoice 自己就踩了这个坑： 它把另一个同名笔记应用的 61K stars 算到了 MemOS 头上。所以它那个"61% 负面"的情感比， 只能当"缺乏真实用户验证"的弱信号，不能当分数级证据用。

怎么读这三个数字

① 事实召回确实是第一梯队。68.9 仅次于 MemoraX，时序推理 56.5 明显强过 Mem0 的 17.4。

② 但宣传最猛的能力几乎归零。"G 上下文学习 / 规则与流程执行"只有 9.82， 而这一项对应的正是它对外讲的 self-evolving memory、skill reuse、crystallized Skills。

③ 有人独立撞到了同一个结论。中文侧报道（36氪）说排名第 2、第 9 的框架在事实召回、多跳、 时序、记忆治理上都强，"规则与工作流执行是它们共同的短板"——第 2 名就是 MemOS。

但 AML 自己也要打折

我直连它的榜单 API 后发现：返回的 65 条记录（商业 15 + 学术 50）全部共享同一个 target_deployment、同一批 excel_*_job_id、同一个提交时间戳， 商业榜 15 条的耗时与 token 成本字段全是 null。

也就是说，公开榜单是一次性从电子表格导入的结果，而不是逐条由站点自己描述的 Add/Search 流水线产出， 没有逐条 run 记录可供复核。这不等于造假（很可能评测在内部跑完后整表发布），但它意味着： AML 的可复现性承诺目前还停留在流程描述层面。而且它只办了一期。

而 LoCoMo 这把尺子本身已经被审计击穿

  • 1,540 道题里 99 道（6.4%）金标答案本身就是错的 → 数学上限 93.57%，满分不可能。

八证据分级：什么能信，什么不能

这是整份记录最该被复用的部分

可核验 高可信

  • AML 商业榜 MemOS = 45.89（第 2），G 类 9.82、G4 = 0——协议把答案与 judge 收归平台，逐类分数可查，版本号明确（v2.0.1）。最强第三方证据。
  • ENGRAM 测得 MemOS LoCoMo = 72.99 ± 0.14——唯一带误差棒的第三方重跑，同 backbone、同 top-k，附 token 与延迟。
  • 官方 issue #881 / #948 / #978 / #1303 / #2277 / #2331 / #2329——一手缺陷记录；#948 由官方 collaborator 自提。
  • 仓库指标：11,333 star / 51 watcher / npm 月下载 6,811——我方直连 GitHub 与 npm API。
  • LoCoMo 审计（93.57% 上限、99 处金标错误、裁判 62.81% 宽松）——独立、方法透明；它约束的是所有 LoCoMo 数字，不只是 MemOS。

须注明口径 中等可信

  • EvoMemBench / MemEye / MedMemoryBench 的逐项分数：经聚合页读取，未直读论文表格，且聚合页标注 "Self-reported"。
  • EverMemOS 论文里的 MemOS 80.76 / 77.80：竞品论文，且 LongMemEval 的 baseline 是引用而非重跑。
  • #2141：子代理单源，本轮未能复核。
  • AgentRecall-X 的行业 landscape：方法透明，但属社区调研，非同行评审。

不能当证据用 须剔除

  • LoCoMo 88.83 / LongMemEval 89.20 / 云服务 92.34 & 93.40——全部出自 MemTensor 自家 OmniMemEval 或官方渠道转载；无第三方复现；与论文自报差 +13 ~ +17 且无版本说明。
  • "HaluMem 全部第一"——HaluMem 由 MemTensor 团队自研（作者即 MemOS 作者），MemOS 既是被测系统又是基准设计方。
  • "+43.70% over OpenAI Memory / 35.24% token savings"——厂商话术，无方法学披露，且与自家 OmniMemEval 的 token 口径（5,400）互相矛盾。
  • RightAIChoice 39% / 61% 情感比——该站自承样本被同名笔记应用污染、stars 张冠李戴。
  • CVE-2025-50738——属于 usememos/memos 笔记应用，与 MemTensor 无关。

九结论：它到底值多少

真实资产

  • 事实召回与时序推理是第一梯队：AML 上 A 68.9 / C 56.5，明显强于 Mem0 的 50.6 / 17.4。
  • 检索延迟极低：在 MemTensor 自家 HaluMem 耗时表里，检索 20.5 / 21.0 分钟为全表最佳（对比 Supermemory 95.5、Memobase 139.9）。这是它最硬的工程亮点，且出自"不利自认"。
  • 迭代极快：约 14 个月、39+ release、53 个 npm 版本；插件覆盖 OpenClaw / Hermes / DSH / Dify。
  • 中文场景与本土合规是结构性优势。

真实代价

  • 写入极慢：同一张自家表里，Medium 下写入 1,028.84 分钟，是 Supermemory 的 3.8 倍；Long 下 1,524.39 分钟，是 Memobase 的 6.4 倍。检索快是拿写入慢换的。
  • 多写换精度：MemOS 抽了 71,793 条记忆、Target P 86.25%、Accuracy 59.55%；而 Memobase 只抽 5,443 条就拿到 Target P 92.24%。多写 13 倍，精度更低。
  • 抗幻觉弱：HaluMem 的 FMR 指标上 MemOS 仅 44.94% / 28.85%，远低于 Memobase 的 80.78% / 85.39%。
  • 治理能力名不副实：AML 的 D 类 44.3、D2 = 0；EvoMemBench 记忆修订排名 7.5；官方 issue #948 自认"不支持冲突感知更新"。
  • 宣传最猛的"自进化 / 技能复用"在受控评测里几乎归零（G = 9.82，G4 = 0）。

把它当"能大幅提升 agent 智能的记忆 OS"，会失望；
把它当"一个检索快、写入重、需要你盯住去重与删除语义的记忆后端"，基本符合观察。
分数请以 AML 的 45.89 和 ENGRAM 的 72.99 为锚，
而不是 README 的 88.83。

十如果已经在自己机器上跑着它

上面所有结论落到操作层面，是这七条

  1. 别用自报分数做选型依据。几百条记忆的规模下任何方案都够用；真正的分水岭在记忆条数上万之后——而那正是 #2277（Recall@1 14.6%、假阳性 100%）与 #2141（24 小时写入 6,076 条、90% 重复）暴露问题的区间。
  2. 盯住三个已知静默失败点：写入后立刻按 id 回查（#2329）、删除后立刻重新检索（#2331）、导入后核对落库内容是否真是抽取结果而非原文（#2290）。这三条都能用一个脚本定期自检。
  3. 定期体检重复率。官方明确自认"不支持冲突感知更新"（#948），重复记忆是结构性问题而非偶发 bug。统计"唯一内容 / 总条数"是最直接的信号。
  4. 敏感内容走本地插件，别走云。记忆是明文存储，且官方文档里查不到加密与数据保留策略。
  5. 保留退出路径。用户侧数据导出未文档化，云版独有能力（知识库、连续对话、调用链分析）不可迁移——至少在本地留一份自己的记忆快照。
  6. DSH 侧确实有更轻的替代：dsh-memgas（ICLR 2026 论文 MemGAS 的四通道检索融合）、dsh-plugin-long-term-memory（npm 月下载 2,180，约为 memos-local-plugin 的三分之一）。只想解决"跨会话记不住"的话，它们是更小的赌注。
  7. 别把 AML 当圣经，也别把它当营销。它的协议设计是全网最干净的，但公开数据是整表导入、缺少逐条溯源，且只办了一期。等第二期（预计 2026-09-20 开放）再决定要不要加注。

调研方法　3 路并行子代理（基准评测 / 社区口碑 / 产品商业）+ 主代理直连核验（GitHub API、AML 榜单 API、npm registry、alphaxiv）。

文中每条结论都带证据等级：我已核验 主代理亲自抓取原始数据 · 子代理核查 由子代理抓取、本轮未二次直连 · 未找到 查证后确认无公开证据。

明确未能核实的项已在正文中就地标注，未做任何推断：Reddit 三路不可达（记为"未找到"而非"没有讨论"）、知乎与 36 氪被登录墙与风控拦截、GitHub API 配额在调研后段耗尽导致 #2141 无法二次复核。
