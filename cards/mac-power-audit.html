唤醒源 8 天里只有同一个：蓝牙 / WiFi 固件在叫醒 SMC （wifibt SMC.OutboxNotEmpty bluetooth-pcie）。 同一时间 sharingd 持着 Handoff 断言，iPhone 正以 BLE 连着这台 Mac—— 三者同时出现，但因果仍属推测：我没有做「关掉蓝牙 / 关掉接力」的对照实验， 这条线索请按待验证处理。

代价也很清楚：那 4 小时里菜单栏一直显示 100%，而电池的真实电量（RawLevel） 已经从 100% 掉到 95.9%。换句话说——深睡根本没有发生，只是掉得慢而已。

07处置清单（按收益排序）

前三条不需要管理员密码；带「最大收益 / 立刻见效」标记的是本轮最直接的收益

  1. 不远程时彻底退出 UURemote最大收益
    它已经连续 169 小时按住「禁止空闲休眠」。若必须常驻，在其设置里关掉「保持唤醒 / 防止休眠」。退出后系统才能在人离开时进深睡。

  2. 处理 WorkBuddy 的熄屏断言屏幕常亮 30 小时
    它是唯一持有 NoDisplaySleepAssertion 的进程；不用时退出，或在其设置中关闭「保持屏幕常亮」。 顺带省掉 745MB 内存与常年 60% 的渲染进程 CPU。

  3. 验证蓝牙 / 接力这条线索（对应 03 的唤醒风暴）
    系统设置 → 通用 → 隔空投送与接力，关闭 Handoff；或临时关闭蓝牙，观察一晚： pmset -g log | grep "^$(date +%F)" | grep -c DarkWake 若从 300+ 掉到个位数，就找到元凶了。

  4. 关掉电池下的 Power Nap，并让插电时屏幕也会熄需要密码

    sudo pmset -b powernap 0      # 电池供电时不再周期性唤醒
sudo pmset -c displaysleep 10 # 你现在插电时屏幕永不熄灭（当前为 0）

  5. 重启一次立刻见效
    已连续开机 7 天 1 小时：压缩器堆积 6.6GB、562 个 launchd 服务、睡眠状态机连续抽搐 13 小时。重启能直接把速率拉回 6–7%/小时一档。

  6. 换 35W / 70W 充电器
    消除「重载时边充边掉」和三个多小时的充电时间。若必须用 30W，就在重载时别指望它回血。

  7. Chrome：清掉空转的标签与扩展
    7 小时里 403 万次空闲唤醒、读盘 16.3GB，绝大多数来自扩展的定时器和后台页。这不是大头（见 04），但顺手可做。

08复测：三条命令，随时自查

不需要管理员密码，直接跑

# 1. 今天电池的真实掉电曲线（15 分钟粒度）
sqlite3 /var/db/powerlog/Library/BatteryLife/CurrentPowerlog.PLSQL \
 "select datetime(timestamp,'unixepoch','localtime'), round(Level) from PLBatteryAgent_EventBackward_Battery
  where timestamp > strftime('%s','now')-28800 group by cast(timestamp/900 as int) order by timestamp;"

# 2. 现在是谁在阻止睡眠
pmset -g assertions | grep -A20 "Listed by owning process"

# 3. 今天醒了几次（正常应在个位数到几十）
pmset -g log | grep "^$(date +%F)" | grep -c DarkWake

方法与局限

  • 数据来源：pmset -g log / -g assertions / -g custom / -g stats、ioreg -rn AppleSmartBattery、 top / ps、vm_stat，以及 macOS 自带的 /var/db/powerlog/Library/BatteryLife/（当前库 + 5 个历史归档，均为世界可读，无需 root）。
  • 能耗归因来自 powerlog 的 coalition 计数表（按进程组累计 CPU / GPU / ANE 能量），单位 nJ，本页换算为 kJ / Wh。
  • powermetrics 需要 root，本轮未采样，因此本页不含逐轨功耗分解；屏占功耗为工程常识判断，非实测拆分。
  • 放电速率为 15 分钟桶均值，含睡眠时段；唤醒次数按 pmset 日志中的 DarkWake 行计数。
  • 「蓝牙 / 接力导致唤醒风暴」目前是相关性推测（唤醒源字符串 + Handoff 断言 + iPhone BLE 同现），未经对照实验证实。
  • 本页所有数字来自 2026-09-29 15:07–15:15 的一次测量，页面可编辑：改动只存在你自己的浏览器里。
