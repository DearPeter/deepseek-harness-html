手写第一个 Agent 循环分水岭

约 12 小时 · 建议分 3–4 天

你会有第一个能自己想办法、自己动手、自己看结果的程序。**这一步跨过去不算学会 Agent，但跨不过去永远学不会。**

先搞懂这几个词

ReAct最有名的一种 Agent 套路，名字是 Reason（想）+ Act（做）拼起来的。模型先说「我打算怎么办」，再说「我要用哪个工具」，你把工具结果告诉它，它接着想下一步。
system 提示词你写给模型的「员工手册」。比如规定它每次只能输出一种固定格式。这是你唯一能稳定控制它的手段。
循环为什么要循环？因为「查天气，超过 30 度就算一下电费」这种任务，一步是做不完的。做一步、看结果、再决定下一步——这就是 Agent 和普通程序最大的区别。

跟着敲

第 1 步：写两个工具函数

工具就是普通的 Python 函数。先用假的天气数据，能跑通最重要。

新建文件tools.py放进 ~/agent-course/
# tools.py
import ast, operator

# 工具一：计算器。注意绝不要用 eval()，它会让别人能执行任意代码
OPS = {ast.Add: operator.add, ast.Sub: operator.sub, ast.Mult: operator.mul,
       ast.Div: operator.truediv, ast.USub: operator.neg}

def _calc(node):
    if isinstance(node, ast.Constant) and isinstance(node.value, (int, float)):
        return float(node.value)
    if isinstance(node, ast.BinOp):
        return OPS[type(node.op)](_calc(node.left), _calc(node.right))
    if isinstance(node, ast.UnaryOp):
        return OPS[type(node.op)](_calc(node.operand))
    raise ValueError("算不了这个式子")

def calculator(expression: str) -> str:
    try:
        return str(_calc(ast.parse(expression, mode="eval").body))
    except Exception as exc:
        return "计算出错：" + str(exc)     # 出错也要返回文字，让模型知道

# 工具二：假天气
WEATHER = {"北京": "晴，32 度", "上海": "多云，29 度"}

def get_weather(city: str) -> str:
    city = city.replace("市", "").strip()
    return WEATHER.get(city, "没有" + city + "的数据")

TOOLS = {"calculator": calculator, "get_weather": get_weather}

这是整节课最关键的一段。你规定得越清楚，模型越听话。

SYSTEM = """你是一个会使用工具的助手。每一步只输出一个 JSON 对象，不要说别的。

要用工具时，输出：
{"thought": "我的想法", "action": "工具名", "action_input": {"参数名": "值"}}

第 3 步：写主循环

整个 Agent 的心脏就是这一个 while。看懂它，你就看懂了所有 Agent 框架。

接着写agent.py同一个文件，接在刚才那段后面
# agent.py
import json, os
from dotenv import load_dotenv
import requests
from tools import TOOLS

load_dotenv()
API_KEY = os.environ["DASHSCOPE_API_KEY"]
URL = "https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions"
MODEL = "qwen-plus"
MAX_STEPS = 6            # 不设上限 = 无限循环 = 一直烧钱

def ask(messages):
    resp = requests.post(URL,
        headers={"Authorization": "Bearer " + API_KEY},
        json={"model": MODEL, "messages": messages, "temperature": 0.2},
        timeout=120)
    return resp.json()["choices"][0]["message"]["content"]

def pick_json(text):
    """模型可能输出 ```json 包着的内容，或者前后带废话，所以要从里面抠出 JSON"""
    start = text.find("{")
    if start == -1:
        raise ValueError("没找到 JSON")
    depth = 0
    for i in range(start, len(text)):
        if text[i] == "{":
            depth += 1
        elif text[i] == "}":
            depth -= 1
            if depth == 0:
                return json.loads(text[start:i+1])
    raise ValueError("JSON 不完整")

def run(question):
    messages = [{"role": "system", "content": SYSTEM},
                {"role": "user", "content": question}]

    for step in range(1, MAX_STEPS + 1):
        reply = ask(messages)
        print("--- 第 " + str(step) + " 步 ---")
        print(reply)
        messages.append({"role": "assistant", "content": reply})

        try:
            action = pick_json(reply)
        except ValueError as exc:
            # 关键：格式错了不要崩，把错误告诉模型让它重来
            messages.append({"role": "user",
                             "content": "你的输出不是合法 JSON（" + str(exc) + "），请重新只输出一个 JSON。"})
            continue

        if "final_answer" in action:
            return action["final_answer"]

        name = action.get("action")
        kwargs = action.get("action_input") or {}
        if name not in TOOLS:
            result = "没有这个工具：" + str(name)
        else:
            result = TOOLS[name](**kwargs)

        print("观察结果：" + str(result))
        messages.append({"role": "user", "content": "Observation: " + str(result)})

    return "超过最大步数，没做完"

if __name__ == "__main__":
    print(run("北京多少度？如果超过 30 度，帮我算一下 30*0.6 是多少"))

function calling模型厂商提供的「官方版」工具调用。你不用再靠抠 JSON 文本，直接告诉模型「我有这几个函数」，它自己决定调哪个、参数填什么，返回给你的就是规整的结构。

import subprocess, pathlib

def read_file(path: str) -> str:
    p = pathlib.Path(path).expanduser()
    if not p.exists():
        return "文件不存在：" + str(p)
    text = p.read_text(encoding="utf-8", errors="replace")
    return text[:4000]      # 关键：截断。不然一个 5 万行的文件会把上下文撑爆

def write_file(path: str, content: str) -> str:
    p = pathlib.Path(path).expanduser()
    p.parent.mkdir(parents=True, exist_ok=True)
    p.write_text(content, encoding="utf-8")
    return "已写入 " + str(p)

def run_shell(command: str) -> str:
    # 危险命令先拦下来
    for bad in ["rm -rf", "sudo", "mkfs", "> /dev/sda"]:
        if bad in command:
            return "这条命令需要人工确认，已拒绝执行：" + command
    r = subprocess.run(command, shell=True, capture_output=True, text=True, timeout=30)
    return (r.stdout + r.stderr)[:4000]      # timeout 必须有，否则一个 tail -f 就能挂死你

def search_code(keyword: str, folder: str = ".") -> str:
    r = subprocess.run(["rg", "-n", "--max-count", "2", keyword, folder],
                       capture_output=True, text=True)
    return (r.stdout or "没找到")[:3000]

记忆与检索：解决真正的瓶颈分水岭

约 14 小时 · 建议分 4–5 天

你会发现 Agent 变笨，往往不是模型不行，而是记事本被垃圾撑满了。这一步让它在长任务里不崩、不忘事。

先搞懂这几个词

token 与上下文窗口token 是模型眼里的「字」，一个汉字大约 1 个。上下文窗口是它一次最多能看见多少 token，超了就必须丢掉一些。
embedding（向量）把一句话变成一串数字。关键特性是：**意思相近的句子，数字也相近**。于是计算机就能「按意思搜索」了。
RAG全称「检索增强生成」。大白话：先去你的资料库里搜相关内容，再把搜到的塞进上下文，让模型基于资料回答，而不是凭记忆瞎编。

import pathlib

def search_keyword(keyword: str, folder: str) -> str:
    hits = []
    for p in pathlib.Path(folder).rglob("*.md"):
        for i, line in enumerate(p.read_text(encoding="utf-8", errors="replace").splitlines(), 1):
            if keyword in line:
                hits.append(str(p) + ":" + str(i) + " | " + line.strip())
    return "\n".join(hits[:20]) or "没找到"

这一步真正的成果不是「我会用多 Agent 了」，而是「我能判断什么时候不该用」。

先搞懂这几个词

多 Agent让几个不同角色的模型互相配合。比如一个写、一个审、一个改。
成本放大三个 Agent 讨论三轮，模型调用次数就是单 Agent 的好几倍。钱和时间都是成倍涨的。
错误传染A 写错了，B 基于 A 的错误内容继续分析，C 再把错误放大。多 Agent 会把小错误滚成大错误。

评估与安全：业余和工程的分界线
